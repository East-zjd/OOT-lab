# 讨论课要求

Lab2作为Lab1的迭代升级，基于学生已提交的Lab1成果及Lab2第一周的开发进展，组织本次讨论课。

## 讨论方式
1. 以小组为单位开展，由组长负责PPT整合与报告展示。
2. 选取小组内具有代表性的代码实现，分别展示3点以上的优秀设计实践与3点以上有待改进的设计点，需详细阐述优秀设计的技术依据及改进方案的具体建议。分析维度可包括但不限于以下方面：
   - 架构设计与模块间依赖关系
   - 设计模式的恰当应用与实现
   - 代码可测试性的设计考量
3. 在上述分析中，需结合Lab2的功能需求，评估当前设计在扩展性方面的表现，重点考察是否符合开闭原则，能够以最小化修改成本引入新功能（需要讨论如何减少复制或修改原有的代码）。
4. 给出使用大模型的心得体会
5. 每组报告时间严格控制在12分钟内，预留3分钟用于问答讨论环节。

## 评价内容
1. 架构设计与模块依赖关系分析
2. 设计模式应用分析
3. 可测试性分析
4. 其他技术维度，包括但不限于大模型应用评估、代码可读性分析、代码异味(Bad Smell)识别
5. PPT的展示以及讨论

## 评分标准

组长评分构成：
- 基础分：10分（默认满分）
- 报告质量：90%

组员评分构成：
- 互评报告（30%）：需提交1-2页的书面报告，对除本组外的其他小组报告进行客观分析，指出其优势与不足，并提供合理的评分（可按照评价内容）
- 小组报告（70%）
